# 架构设计

> 本文档描述 QQ-Agent for Linux 的分层设计、通信契约与配置形态。
> 当前处于设计阶段，接口可能调整；实现落地后本文档会同步更新。

## 设计原则

1. **进程隔离**：协议端（SnowLuma）与本项目是两个独立进程，通过标准网络协议通信，不做进程内嵌。
2. **契约唯一**：两者之间只有 OneBot v11 一条契约线，不引入私有协议扩展。
3. **依赖单向**：上层依赖下层的抽象接口，下层不知道上层的存在；协议端只在接入层被感知。
4. **无状态优先**：核心层尽量保持可重启，需要持久化的状态集中在会话存储中。

## 分层职责

| 层 | 职责 | 明确不负责 |
| --- | --- | --- |
| **接入层** | 连接管理、断线重连、心跳、鉴权、事件反序列化、动作封装 | 业务逻辑、会话判断 |
| **核心层** | 事件总线、会话管理、上下文存储、任务调度 | 具体功能实现、协议细节 |
| **Agent 层** | 意图理解、多轮对话、工具调用、记忆检索 | 网络通信、消息拼装 |
| **插件层** | 用户自定义功能模块 | 修改核心行为、绕过事件总线 |

## 通信链路

```
QQ 客户端
   │  原生会话
   ▼
┌──────────────────────────┐
│  SnowLuma（独立进程）      │   WebUI :5099
│  QQ 会话 ─► OneBot v11    │
└────────────┬─────────────┘
             │  OneBot v11 over WebSocket
             │  (正向首选 / 反向备选)
             ▼
┌──────────────────────────┐
│  接入层                   │
└────────────┬─────────────┘
             │  内部标准事件
             ▼
┌──────────────────────────┐
│  核心层 ─► Agent 层 ─► 插件层 │
└──────────────────────────┘
```

### 连接方式

| 方式 | 本项目角色 | 说明 | 优先级 |
| --- | --- | --- | --- |
| 正向 WebSocket | 客户端 | 主动连接 SnowLuma 的 WS 端口，自动重连 | ✅ 首选 |
| 反向 WebSocket | 服务端 | 监听端口，由 SnowLuma 回连；适合本项目在 NAT 后的场景 | ✅ 备选 |
| HTTP / 上报 | 服务端 | 请求响应式，无长连接，时延与实时性较弱 | ⏳ 后续 |

### 一次消息往来的时序

```
QQ 用户                SnowLuma              接入层            核心层
  │                       │                    │                 │
  │ ── 发送消息 ──────────►│                    │                 │
  │                       │ ── event: message ─►│                 │
  │                       │                    │ ── 内部事件 ───►│
  │                       │                    │                 │ 会话定位
  │                       │                    │                 │ 上下文加载
  │                       │                    │◄─ 发送动作请求 ─│
  │                       │◄─ action: send_msg ─│                 │
  │◄── 收到回复 ───────────│                    │                 │
```

**接入层的两条独立通道**：事件入站（接收 OneBot 事件）与动作出站（发送 OneBot 动作）。两者共用同一条 WebSocket 连接，但处理流程互不阻塞。

## 核心数据结构

### 会话标识

OneBot v11 的消息事件分三个层级，会话键设计如下：

| 场景 | 会话键 |
| --- | --- |
| 私聊 | `private:{user_id}` |
| 群聊 | `group:{group_id}` |
| 群内定向（按用户隔离上下文） | `group:{group_id}:user:{user_id}` |

会话键是上下文存储与插件状态隔离的基本单位。

### 内部事件

接入层将 OneBot 事件转换为内部标准事件后投递到总线。内部事件不暴露 OneBot 原始字段名，以便未来更换协议端时不污染上层。

### 配置形态（草案）

```yaml
# ~/.config/qq-agent/config.yaml
protocol_end:
  # 正向：本项目主动连接 SnowLuma
  mode: forward
  url: ws://127.0.0.1:3001
  access_token: ""

  # 反向（mode: reverse 时生效）
  # listen: 0.0.0.0:8080

  reconnect:
    initial_delay_ms: 1000
    max_delay_ms: 60000
    backoff: exponential

core:
  session:
    ttl_hours: 72
    storage: sqlite          # sqlite | memory
    path: ~/.local/share/qq-agent/sessions.db
  log_level: info

agent:
  enabled: false
  context_window: 20         # 每会话保留的近期消息数

plugins:
  enabled: []
  dir: ~/.local/share/qq-agent/plugins
```

> 字段为设计草案，尚未实现。实际字段以发布版本为准。

## 插件模型（规划）

插件形态尚未最终确定，候选方向：

- **清单文件 + 入口模块**：插件目录含 `plugin.toml` 描述元信息（名称、版本、所需权限），入口导出固定生命周期钩子。
- **生命周期**：`on_load` → 事件订阅 → `on_unload`，支持热重载。
- **能力边界**：插件只能通过核心层提供的接口访问会话与发送消息，不直接持有协议端连接。
- **权限声明**：插件在清单中声明需要的事件类型，核心层只投递其声明的事件。
