# 2 核 2G 服务器适配实现状态

日期：2026-10-12。本文记录当前 checkout 的实现和仍需线上验收的项目。新版已部署到目标 ECS，QQA、SnowLuma 1.14.22 及临时 QQ 登录窗口均已通过公网浏览器验证；旧程序已清理，保留一份回滚备份。实际部署记录见 [server-deployment-20261012.md](../../构建产物/部署资料/server-deployment-20261012.md)。源码测试与真实 QQ 收发、长期稳定性验收分别记录。

## 已实现并在本机验证

- 纯 Node 服务器入口、固定 3210 服务器模式、远程控制台登录、初始密码文件（0600）、会话过期、登出、来源检查、SSE 客户端上限和慢连接断开。
- `server-2c2g` 默认资源边界：核心并发 1、待处理群上限 32、后台工作限流、媒体/视频默认轻量模式、OneBot 消息大小限制、扩展热重载关闭。
- 服务器事件接入使用 SQLite WAL 磁盘队列，单并发处理，预设最多 512 条、积压最多 64 MiB、单事件最多 4 MiB，数据库页面预算 96 MiB。成功后删除，失败指数退避，达到重试上限后保留为 deadletter；失败记录计入容量，队列满时明确拒绝新事件。已登录且来源验证通过的 `/api/runtime/incoming/retry` 每次最多重试 100 条失败记录。
- 事件队列和聊天 SQLite 都使用 `synchronous=FULL`。队列 UUID 与事件序号组成 `sourceEventKey`，聊天后端保存并索引该来源，重启、poke、迁移及回滚保留去重信息。投递语义为至少一次；聊天来源去重不构成 QQ 外部发送的原子事务保证。关闭队列有数据库 deadline，核心还会等待活动处理函数结束，之后才关闭聊天库和释放锁。
- 聊天消息 SQLite WAL 后端：索引查询、最多 2000 条/8 MiB 的读取预算、分批未读、成员摘要和 JSON 兼容缓存。新空数据目录在 Node 22.16+ 上使用 SQLite；已有 JSON 不会自动改写。JSON 写入失败时丢弃未持久化的缓存，避免重试被误判为已保存；历史文件损坏、不可读或结构异常时保留原文件并报错，不用空聊天覆盖历史。服务器 JSON 单聊天档案读写预算为 8 MiB，超限提示停核心、备份后离线 migrate；其他群仍能恢复未读，不因一个坏档案阻塞。
- 存档 `GET /api/chats/(group|private)_<id>/messages` 支持 `offset`、`limit`，默认及最大每页 500 条；`offset` 表示跳过最近多少条消息。响应提供 `total`、`nextOffset`、`hasMore`，SQLite 的字节预算提前结束一页时按实际返回条数推进，较旧消息仍可继续读取。界面首屏最多请求 500 条，滚动追加最多请求 200 条；刷新已加载历史也分成最多 500 条的请求，合并去重，并阻止旧实例、旧选中项的迟到响应覆盖当前存档。首屏遇字节限制形成短页时直接显示该页，不为凑满行数继续批量下载。JSON 后端使用相同分页接口；服务器读取前拒绝超过 8 MiB 的旧 JSON 聊天文件，保留原件并提示停止核心后离线迁移。
- `/api/media-data` 每次最多 20 张图片，`server-2c2g` 预设约束整批原始图片总大小为 8 MiB，而非每张各 8 MiB；base64 编码会另有约三分之一的体积增加。请求共用媒体处理队列，预设并发 1、总任务数最多 16、排队超过 30 秒拒绝；慢响应直到发送完成或连接关闭才释放处理额度。单图、整批字节或图片数量超限返回 413，队列超限返回 429。外部 OneBot 的 `file` 属于远端，不读取本机同名路径，只通过受 DNS、重定向和私网检查保护的 URL 下载图片。`resources.localMedia=false` 关闭默认重媒体运算，保留这个有总量限制的显式取图功能。
- `scripts/message-storage.mjs` 提供停止核心后执行的 `migrate`、`export`、`rollback`。Worker 流式处理历史，迁移保留 JSON 原文件，逐群验证数量/字段哈希/未读索引/SQLite 完整性；中断不切换后端，回滚先保留迁移后新增消息。
- 核心与离线存储维护共用 `qq-agent.lock`。同进程重复构造和竞争进程都不能夺取或释放持有者的锁；构造失败会清理已创建资源后释放锁。死 PID 锁通过独立恢复 guard 串行复查后清理，格式异常的锁需要先检查。
- OneBot HTTP 与 WebSocket 都受配置的响应/消息体积上限约束。停止时中止 HTTP 响应头等待和流式响应读取，禁止新请求；发送队列取消未执行消息，并等待在途确认发送的存档续执行。Agent、记忆整理和提醒任务完成收尾后，才关闭聊天数据库和释放实例锁；提醒循环停止后不会重新建立定时器。
- 服务器历史未读处理重新检查当前白名单、黑名单和 OneBot 连接状态。断线保留未读，重连会恢复既有待运行任务并扫描积压，无需等待下一条新消息触发。
- 用户扩展目录迁移到数据目录，禁用的 Skill/插件不导入执行；市场和 ZIP 安装路径受限并有下载、解压和字节边界。仓库原有 bundled `skills/`、`plugins/` 已移除，用户自行从 Skill 市场选择。
- 服务器归档由当前 checkout 和 exact lock 构建，排除 Electron、协议端二进制、QQ、用户数据、密钥、旧 `ci-input` 归档；manifest 记录提交号、脏工作树和逐文件 SHA256。systemd 核心 unit 与 QQ/SnowLuma 独立 unit 模板分离，安装器保留 current/previous release 和数据目录。
- 安装器在切换前核对已有 release 链接、现有数据目录与参数一致、端口有效；切换后等待 `/api/auth/session` 健康检查，最多 40 次、间隔 0.5 秒、单次请求超时 800 ms。失败时恢复受管核心的旧 release、unit 和服务状态。如果没有旧核心 unit，不会尝试恢复桌面 Electron，也不会停止 QQ 或 SnowLuma。Node 22.17.1 下载脚本有固定 SHA256。
- 每个 release 的 unit 快照保存在安装根目录 `unit-state/`。手动回滚恢复旧 release、unit 和 Node 路径，保留操作前的启停状态；若旧版本健康检查失败，则恢复本次操作前的版本和 unit。缺快照、Node 已不存在或端口非法时拒绝切换。

## 会话详情分页与原件下载

服务器的 `GET /api/sessions/:id` 使用 `offset`、`limit` 分页。历史 JSON 在短生命周期 Worker 中流式扫描，主线程不会对详情档案执行全量 `readFileSync + JSON.parse`；运行中会话直接从现有对象生成相同的受限显示窗口。显示投影和分页都不修改会话原件或运行中对象。

| 项目 | 当前边界 |
| --- | --- |
| 每页过程记录 | 默认及最大 100 条；消息投影累计预算 512 KiB，达到预算会提前结束当前页 |
| 单条记录与元数据显示 | 单条记录投影预算 64 KiB；元数据投影预算 256 KiB；字符串字段按约 16 KiB 的 JSON 编码预算缩短并标记 |
| 投影复杂度 | 每个对象/数组最多 100 项、最多 4096 个遍历节点、深度最多 8 层 |
| 历史详情执行队列 | 并发 1，总任务数最多 4；超额或排队超过 30 秒返回 429 |
| 历史解析线程 | V8 old generation 96 MiB、young generation 16 MiB；读取超过 120 秒终止线程并返回 504 |
| 原始 JSON 解析 | 单个字段/消息和累计顶层元数据最多 4 MiB；超限返回 413，保留原件并提示下载 |
| 内部历史完整读取 | 服务器 `get()`/`peek()` 在读取前检查文件大小，超过 8 MiB 抛出可显示的 413 错误；小档案保留原有完整读取行为 |

页面显示当前范围和总条数，“查看后续记录”替换当前窗口，“回到开头”返回第一页；后端的 `nextOffset` 指向下一条尚未返回的记录，字节预算提前结束时不会跳过消息。刷新保留当前页，旧实例、旧选中项和旧页的迟到响应不能覆盖新页。长内容有明确缩短提示；JSON 模式也只显示当前页的投影，需要完整输入/输出时使用原件下载。

当前实例详情页提供 `GET /api/sessions/:id/download`，在统一控制台认证和来源检查后，从固定会话目录流式发送磁盘 JSON。下载不进行 JSON 解析或档案大小级的缓冲；文件只打开一次，长度检查与读取使用同一 FileHandle，运行中原子替换档案不会导致声明长度与读取文件不一致。运行中下载反映最近一次已落盘状态；跨实例视图不提供本机下载链接，应打开对应实例的控制台下载。

每次历史分页仍扫描该档案，当前没有随机位置索引。超限、损坏或扫描期间档案变化时，页面给出错误并允许下载现有原件；详情关闭会等待已登记的读取任务完成，排队任务在执行前重新检查关闭状态。同步 `get()`/`peek()` 仍供小档案内部完整读取使用，服务器历史失败会话超过 8 MiB 时明确拒绝重试，提示下载原件并发起新会话；拒绝发生在恢复未读和修改会话之前。普通详情 HTTP 请求使用流式分页，不受整档 8 MiB 上限约束。

## 审查发现闭环

- 停止后排队消息继续发送并写入已关闭 SQLite：发送准入关闭、可中止等待、在途存档屏障及核心关闭顺序已修复。
- OneBot HTTP 原先绕过 WebSocket `maxPayload`：声明长度与实际流字节分别检查，响应头/响应体停止中止已覆盖。
- 断线待运行队列停滞、旧白名单积压误处理、提醒停止后重建定时器：重连恢复、当前规则检查和循环代际保护已修复。
- 入站队列 deadline 后处理函数仍续执行：核心额外等待 `waitSettled()`；poke 名称查询后增加中止检查，关闭聊天库及释放锁前保留依赖。
- 历史详情主线程全量解析：Worker 流式分页、受限显示窗口及原件流下载已实现；大型历史、队列溢出、单字段超限和页面响应乱序已有专项回归。
- 历史失败会话重试的同步整档解析：`get()`/`peek()` 的服务器 8 MiB 读取前保护已实现，拒绝时不读完整档案、不恢复未读、不修改原件；小历史的原地重试仍可使用。
- 存档接口忽略 offset、SQLite 限量窗口之外的消息无法浏览：服务端实际分页和界面按需追加已修复，JSON/SQLite、超过 2000 条的旧消息和字节限制短页均有回归。
- 多图片同时转为 base64 的聚合内存及外部协议端同名本机文件读取：整批预算、共享并发、慢响应处理额度及远端文件拒读已修复，超额请求明确报错。
